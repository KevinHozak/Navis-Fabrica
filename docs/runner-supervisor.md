# Durable runner supervisor

The supervisor runs a batch only after an explicit submit. The CLI and desktop bridge use the same typed `supervisor_protocol` operations and shared data root. `batch-preview` is storage-free and returns the normalized request, admission plan, and a fingerprint bound to the request, current settings bytes, and worker executable identity. Submit must return that fingerprint; a changed request, settings file, or worker requires a new preview.

Each preview issue reports `eligibility` (`eligible`, `blocked`, or `waiting_for_dependency`) and routing reasons. Its task entries show the selected provider and model, whether the assignment came from an explicit task assignment or a settings default, and any capability or policy mismatch. A blocked preview remains reviewable, but submit independently repeats strict route and policy validation and rejects blocked work. Dependencies linked to another selected batch job remain waiting until that predecessor is verified; explicit closed-external evidence is recorded in the request.

Batch state and controls live in `batches.sqlite3`; attempts, lease fencing, job events, and exact provider process identities live in `jobs.sqlite3`; budget reservations and settlements live in `budgets.sqlite3`; workspace effects and verification evidence remain in their existing stores. These databases stay separate because their schema migrations are independently owned.

Submit persists the immutable batch and launches detached `fabrica-worker` processes. Each worker waits for its launch registration, validates its own PID and Windows creation time, and claims only job IDs linked to its batch. Workers renew job leases, periodically reconcile expired scoped leases, persist provider dispatch intent and process identity before the runtime continues, and settle measured usage. Unknown usage remains reserved for explicit reconciliation. Paid OpenRouter tasks require an immutable per-task policy with a fresh price ceiling, verified context, output/token/call caps, and an aggregate cost cap. A loopback gateway strips credentials from the child process, admits each upstream call against the parent reservation before dispatch, caps the request, and records provider-reported usage; unknown child usage keeps the parent reservation unresolved. Custom runtimes remain rejected. Local runtimes report zero API cost only when telemetry explicitly identifies a local no-charge run.

Pause and stop prevent new claims while current work reaches a terminal checkpoint. Cancel requests job cancellation and terminates only a recorded provider process whose PID and creation time still match. Cancellation and worker crashes do not retry automatically. The reconcile operation reports expired batch jobs and whether the recorded process identity is still live; a human must resolve ambiguous process/workspace effects before retry.

Implementation work runs in an isolated managed worktree and records the exact allowed changed files. It never commits, pushes, publishes, merges, or deploys. A proposed completion remains pending until declared checks and an independent, read-only Codex reviewer verify the exact code snapshot. Reviewer and implementation task identities must differ. Repair is limited to two persisted rounds; interrupted rounds remain interrupted, and exhausted rounds fail verification. Verification work with an unfinished durable check or review checkpoint moves to human input rather than replaying silently.

The worker binary accepts only the shared data root, batch ID, and worker ID. It does not read or execute provider instructions from batch-control records. UI code cannot choose an arbitrary executable; the bridge supplies its packaged sibling worker. CLI callers may supply an explicit trusted absolute worker path.

## Current limits

Usage settlement depends on what each runtime reports. Missing token or cost telemetry remains unresolved and consumes reserved capacity; operators must reconcile it from authoritative evidence. Paid OpenRouter execution is limited to explicitly submitted tasks with a verified policy and capped local gateway; no live paid-provider call is required for offline regression tests. A paused worker exits after reaching a safe point; resume starts a fresh worker slot. Status returns all jobs in the admitted batch (up to 128), with checkpoint payloads capped at 20 per job, 4 KiB each, and 64 KiB total. Oversized runtime output is projected as a UTF-8-safe suffix within the 4 KiB serialized limit, with truncated/originalBytes metadata; the full bounded record stays in SQLite. Jobs expose checkpointsTruncated when count or aggregate limits omit evidence, while their state remains readable. Event reads are cursor-based and bounded to 100 events per call. Reconcile reports ambiguous work and does not assert that workspace effects are safe to retry.

Offline tests cover launch-slot identity registration, control transition boundaries, UTF-8-safe output truncation, scoped job APIs, and the production runtime/verification path. Synthetic provider fixtures validate process lifecycle without contacting live providers.

## Windows startup and worker ownership

A foreground `run-batch` is a supported explicit managed-worker host, independent of the requesting Codex turn and Fabrica window while its CLI terminal/session remains open.

No service, scheduled task, or startup item is installed automatically. A human may start the supported foreground CLI in an ordinary terminal outside Codex/Fabrica for unattended hosting; keep that terminal open. Window closure does not stop the foreground host. Reconnect the UI with the same state and batch ID and never press Start again for readback.

On Windows Job Objects that disallow breakaway, submit returns typed `WORKER_LAUNCH_FAILED` after admission. Inspect status and explicitly use `run-batch` with the SAME confirmed request/preview fingerprint and trusted worker executable; do not resubmit or retry. Re-running `run-batch` on an existing paused/waiting resumable batch reattaches hosted workers idempotently and preserves job IDs, attempts, budgets, and absolute deadline.

```powershell
& $runner run-batch --data-root $state --worker-executable $worker --batch-request $confirmed --preview-fingerprint $fingerprint
```

Workers own exact scoped job IDs, lease fences, and durable dispatch intent. Cancellation targets only matching owned process identities, never name-based process sweeps. Host closure/logoff/reboot may interrupt work: durable state survives, but explicit reconciliation of PID+creation identities, workspace effects, and held unknown usage is required before safe retry. Keep the machine awake; sleep/suspend stops progress and can expire leases/deadlines, and Fabrica changes no sleep settings automatically. Remote inference needs working network/provider auth; local fake/Ollama checks can be offline per adapter. Network/auth retries are bounded; input/approval/unknown effects become `needs_input` or `reconciliation_required`, never silently repeated. Process reconstruction tests cover cold host recovery, not physical reboot/power-loss durability. No claim of hostless service, terminal-close survival, auto reboot resume, general sandbox, or production overnight readiness.
