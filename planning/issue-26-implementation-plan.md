# Routing-P2 implementation plan

## User Review Required
None. Issue #26 authorizes scoped implementation, verification, commit, push, and pull request creation. Do not merge.

## Acceptance Criteria

| Criterion | Implementation | Verification |
| --- | --- | --- |
| Deterministic complexity and pace rules | Rust routing evaluator applies complexity-derived context/reasoning requirements and Fast, Balanced, Thorough, or Economy ordering. | Fixture tests cover eligibility and deterministic ranking. |
| Eligibility, measured signals, and manual override | Required tools, context, and local-only privacy filter candidates first. Fresh measured usage and latency inform ranking; unknown/stale/estimated signals do not. Eligible manual choices override ranking. | Tests cover missing/stale signals, unsupported capabilities, privacy, and override. |
| Explainable recommendation and timing preference | Return selected model, every candidate's eligibility/rejection and ranking reasons, plus an explicit desired-time preference status without promising completion. | Tests verify reasons and timing language; frontend displays alternatives. |

## Proposed Changes
- `src-tauri/src/routing.rs`: request/candidate/decision contracts and pure deterministic evaluator.
- `src-tauri/src/lib.rs`: expose the evaluator as a scoped Tauri command.
- `src-tauri/src/providers.rs`: optional estimated model quality rating with backward-compatible deserialization and validation.
- `src/settings.ts`, `src/ProvidersPanel.tsx`, `src-tauri/permissions/autogenerated/`: typed UI, model rating input, routing controls and decision results.
- `src/styles.css`: responsive routing decision presentation.

## Verification
- Focused routing/provider Rust tests; `cargo fmt --check`, `cargo test --locked` focused filters, `cargo check --locked`.
- `npm run build`, staged diff review, and `git diff --check`.
- No live provider data will be claimed unless a live probe is run and reported separately.
