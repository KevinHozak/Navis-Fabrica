# Runner workspace isolation

`runner_core::isolation` prepares issue-scoped Git worktrees and records ownership. Callers provide a canonical project path, an ignored managed worktree root (normally `.worktrees/`), an exact verified base commit, the issue snapshot fingerprint, isolated build root, and explicit verified predecessor commits. Locks and ownership records are stored under Git's canonical common directory, so app and CLI instances with different local state roots discover the same repository ledger. Ownership records remain constrained to the configured managed worktree root and repository identity before reuse or cleanup. The module never switches, stashes, resets, commits, pushes, or cleans the primary checkout; it does not use GitHub or require a remote.

## Locks and execution

Repository metadata locks and ownership records are created under Git's canonical common directory, so multiple app/CLI state roots share the repository ledger and serialize shared Git operations. A per-issue writer lock remains held by `WorkspaceLease` for the lifetime of task writes. Call `lock_repository_metadata` around integration, version changes, release mutations, or other repository-wide operations. The worktree and its build output are separate; build roots inside or overlapping the repository are rejected. Git operations use the shared Windows hidden-process helper, a 30-second deadline, and a 1 MiB output bound.

Preparation verifies full commit IDs and source snapshot fingerprints before creating a branch worktree on `codex/runner/<issue>`. Predecessors need their issue identity, commit, source fingerprint, and explicit verification evidence. They are cherry-picked in caller-declared order with Git's source marker, unless already ancestors of the exact base. Reuse requires the same base, issue snapshot, predecessor set, branch, build-output path, clean-or-recorded dirty-path set, and predecessor history. A mismatch is surfaced for review; it does not trigger a fresh checkout.

## Ownership, recovery, artifacts

Ownership records retain repository/worktree paths, branch, verified base, issue snapshot, predecessor and owned commits, authorized changed paths, source fingerprint, isolated artifact paths, timestamp, and lifecycle state. `record_owned_changes` accepts only an exact match to porcelain status. `record_owned_commit` records only a commit reachable from the owned worktree head. `record_artifact` accepts only an existing artifact inside the job's isolated build-output directory.

`recover_workspace` inspects a persisted owner and Git worktree registration without creating a replacement or clearing a lock. A `Preparing`, `Recoverable`, or `CleanupPending` record cannot be reused as ready work. Metadata denial, output denial, path denial, and lock contention are distinct error classes. A permission or interrupted Git operation keeps the ownership record for inspection. Cleanup requires an exact owner record, a registered path under the configured managed root, and a clean worktree; dirty work is preserved. No force-remove or branch deletion is performed.

The synthetic repository tests cover local-only discovery, dirty-primary preservation, exact worktree reuse, one-writer locking, predecessor cherry-pick provenance, build/source separation, conflicting edits, tampered ownership paths, and cleanup refusal. They do not exercise live providers, Tauri wiring, process supervision, permissions on a locked-down Windows ACL, or unattended stale-lock breaking; stale locks deliberately require a separate recovery decision.
