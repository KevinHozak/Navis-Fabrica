# Portal text helper — S012 legacy standalone path and S027 native shared-host path

S012 documented the standalone helper-only integration. Its preserved-default statements below describe that historical scope. S027 adds a separate explicitly selected native panel and bridge; existing tasks/provider profiles, Codex subscription defaults, optional Aider paid admission, jobs and coding runner defaults remain unchanged.

## Historical S012 standalone setup (legacy, not the S027 native setup)

The S012 standalone path used `scripts/model_helper.py run --task portal-extract` only with a protected `--portal-profile`, existing private `--config`, and persisted `--operation-id`/`--run-id`. Its profile targeted a separately reviewed Portal 0.2.1 release and bound the same existing helper ledger, policy commitment, scoped app-key reference and call/run ceilings. No active profile or key shipped. Private mode and other helper composition/probe modes were refused for that path. Denial, unavailability, cancellation, duplicate or unknown billing never invoked a direct OpenRouter/Ollama fallback.

Portal owns authoritative provider accounting. Fabrica retains its same existing helper daily-cap ledger/history/unknown holds and adds a conservative `portal-reference` cap mirror, with globally unique operations and durable per-run limits. Do not sum that reference and Portal's charge as separate purchases. No old coding-run/pilot grant is imported, no historical ledger is replaced, and no cap is increased. Unknown work remains reserved; changing the operation ID to retry it is not authorized.

The [Portal integration runbook](https://github.com/KevinHozak/Navis-Portal/blob/main/docs/fabrica-integration.md) owns the complete protected profile schema, offline commitment command, supported package/runtime, accounting semantics and rollout gates. Actual CLI/bootstrap subprocess tests run from Portal with a fake Portal/upstream, generated text and temporary dummy app credentials; a test-only socket guard denies non-loopback traffic. The existing Fabrica helper tests cover preserved default routes. Independent external review and live rollout are separate from this offline implementation.

The S012 implementation did not perform model inference, change a real credential/policy/budget/ledger, install a background service, change app defaults or deploy. S027 likewise remains source-only; later live use still requires fresh exact endpoint/token/privacy/fee evidence and separate authorization. Old pilots do not carry over.

## Explicit shared-host mode — PORTAL-S027

The schema 1 standalone CLI/profile remains unchanged. A separately reviewed schema 2 profile adds `"host_mode": "shared"` and opts into `--portal-shared-host`. The native backend also supplies `--portal-host-generation` from its acquired host connection; the helper checks the current generation and refuses without reacquiring if it changed. Standalone CLI shared mode can omit the generation and lets the helper acquire the registered host. These flags require the explicit `portal-extract` profile path and cannot fall through to ordinary routes. Prompt text remains transient on stdin. Existing Portal accounting, Fabrica mirror caps, operation/run identity and unknown-hold semantics remain authoritative.

The native UI is an explicitly selected `#portal` panel; ordinary routes and startup do not probe or acquire the shared host. Native launch policy is read only from `%USERPROFILE%/NavisFabrica-Portal/launches/fabrica-extract.json`. That strict schema 1 document binds contract `fabrica.portal-extract/1`, stable run ID `fabrica.portal-extract`, the registered runtime executable and hash, the helper/config/feature-profile paths and hashes, and hashes for exactly the four reviewed helper scripts. The fixed paths are `helper-config.json`, `portal-state/fabrica-extract.json`, and `fabrica-helper/scripts/{model_helper.py,portal_bridge.py,ledger_fence.py,portal_private_files.py}` under the registered Portal root. Helper script hashes use UTF-8 without BOM and LF line endings, matching `src-tauri/portal-helper-source.json`; package copies must preserve those normalized bytes. The native launch profile and reviewed schema 2 feature profile are installation-owned inputs: no profile, key, credential, cap, or real ledger is created by this change. This contract and its offline evidence are summarized in the [S027 integration record](https://github.com/KevinHozak/Navis-Portal/blob/main/docs/s027-fabrica-shared-host.md).

The renderer supplies only the bounded prompt and stable operation ID. It persists unresolved operation IDs without prompt or result text, never retries an unknown operation, and requires an explicit new operation after the user reviews an uncertain outcome. Native output accepts only bounded allowlisted fields; complete or partial text is transient, while unknown/malformed billing returns no text. Cancellation and timeout terminate only the helper process started for that operation and preserve the shared Portal host.
