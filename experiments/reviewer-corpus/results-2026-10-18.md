Assertion failures establish the buggy labels; compiler errors, timeouts and zero-test filters do not.

## Method

Both formats used GPT-6 Luna, medium reasoning, Codex CLI 0.162.1, fresh ephemeral read-only sessions and the production-equivalent JSON output schema. Each reviewed every case twice: 16 trials per format, 32 scored calls. At most two ran concurrently; submission order alternated. Both had the same 120-second wall limit and soft 600-word response limit. Token budgets were not hard-capped or equalized.

The baseline preserves the current review policy but replaces live Git/workspace obligations with a whole-artifact specimen contract. The candidate adds the original claim/evidence/verification instruction unchanged. Labels, pairing, revisions and executable outcomes were withheld. Models had source and requirements, not tool access or test results. No reviewer tool calls were observed. Model/effort are recorded from the CLI invocation; backend execution settings were not independently attested.

A primary-agent source audit classified every finding against the executable specimen evidence. This adjudication was not independent or blinded. Disposition-only counters are retained separately: a rejected buggy case is not credited unless its findings demonstrate a real in-contract defect. Withdrawn suspicions and satisfied requirements left in `findings` remain unsupported; on clean controls they still block the gate.

The baseline missed both literal SVG failures in one repetition while still returning `passed=false` with a non-defect explanation. The structured format caught those failures, but missed one of the two nested-path defects in another repetition. Both formats repeatedly described compliant behavior or withdrew a suspicion while leaving it in `findings`; this would still block Fabrica's gate. Other false positives misread candidate ordering or XML attribute handling despite passing executable controls.

## Calibration and limits

An earlier 24-call calibration used “exactly the supported roots,” which could be read as an exclusive list, and did not exclude competing logo files clearly enough. Those results are excluded from the final accuracy comparison. The contracts were rewritten as explicit fixture scenarios, the exposed nested family became a target/regression set, and an unexposed encoded-reference variation became the final held-out pair. A construction-only intermediate eight-case manifest was verified but never used for model trials; the final build strengthened recognized oversized-PNG fixtures and froze dependency resolution before inference. All earlier evidence remains private rather than overwritten.

The final encoded-reference clean control failed under both prompts, so the predeclared no-regression/held-out adoption gate failed. `workflow_evidence.py cycle` returned **revert**. No active runtime prompt or settings had been changed, so no baseline rewrite or rollback was needed. The requested corpus, executable harness and comparison tools are retained separately; they do not adopt the candidate instruction.

This is a small, correlated corpus with source-only review and one non-blinded evaluator. Two repetitions do not establish statistical superiority. The controls are clean only for their specimen contracts, not globally. PNG markers test byte selection rather than rendering. See [README](README.md) for reproduction commands and boundaries. A useful later trial would test an unresolved-findings-only output rule or actual reviewer access to executable verification, with fresh held-out cases and explicit authorization.
